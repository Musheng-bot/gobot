# Rush

rush是一个导航的架构包，可以用来跑通一个正常的导航程序

## 感知

导航的前提是拥有感知能力，这点主要依靠导航包中的map模块提供

### 全局地图

全局地图通常直接由先验地图提供，只读取先验地图中的梯度图来判断障碍物信息，并可以选择是否开启膨胀

### 局部地图

局部地图选择采用`ROG-Map`方案，对3D点云进行修缮，形成2D的ESDF场，辅助规划

### 地形识别

对于台阶一类地形，我们暂时没有识别手段，在局部地图层面，希望未来能做一个点云分割识别的方案，真正区分地形和正常行驶的车辆或者其他障碍物

### 语义拓扑地图

对先验地图进行不同的区域划分，令其能表述不同的语义信息，比如`高地`, `台阶1`, `基地`等

### 几何拓扑地图

是对一种特殊地图，由不同节点和边构成，表述的是一种连通关系，主要依靠分岔路指示信息

## 规划

### 语义规划

根据比赛规则将全局先验地图划分为多个区域，决策端负责指出不同区域的通过顺序，例如`高地->台阶1->基地`，等划分

### 全局规划

全局规划期望采取跨节点的`TopoPlan`思路，在获取目标点和机器人位置后，通过全局先验的几何topo地图和决策端规定的区域通过顺序选择寻找可行的拓扑路径，确定行进大方向。
全局规划不再规划完整的路径，而是只采用几何拓扑生成的参考路径，也就是不负责具体的路线制定

### 局部规划

局部规划首先规划出一条短线路用于跟随，随后经过优化

### 速度规划

速度规划频率需要保持在40Hz上下

## 其他功能

### 地形跨越

地形跨越要求较高，需要在对准之后一步到位，并且不能允许它在识别时看不见动态障碍物，或者把楼梯误认为障碍物

### 重规划策略

如果被阻挡或者偏离路线都需要采取一定的重规划策略，如果局部规划频率较高可以考虑舍弃
